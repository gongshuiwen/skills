# Documentation Baseline Maintenance

## 目标与边界

让项目文档随有效系统契约持续演进，以最小必要的维护成本保持**准确、一致、自解释、可发现、可追溯**；不以文档数量、篇幅或新增文件数衡量产出。

- 仅审查当前文档任务或系统变更涉及的文档及必要引用，不扩大到无关整理；不影响已记录行为、契约或使用方式的内部变更，可不修改文档。
- 遵循项目现有目录、文档分类、风格、生成流程及监管或审计留存要求；不强制引入新工具、模板或文档平台。

## 工作流

### 1. 确认任务范围与事实依据

- 独立编写、审查或重构文档时，先明确主题、目标读者与用途；涉及系统变更时，识别受影响的用户操作、公共接口、配置、部署步骤、架构职责、兼容性及故障处理方式。
- 结合已确认需求与契约、代码、配置、测试和正式设计决策核实事实；**当前实现不一定代表正确的预期行为**，存在冲突时先核实，不为迎合实现而篡改明确契约。
- 区分**当前有效、规划中、已废弃**的内容；不得将推测、草案或未实现能力描述为现状；不同版本与环境应明确适用范围。

### 2. 审查现有文档与信息缺口

- 定位相关文档及索引，识别权威位置，检查内容失效、重复、冲突、职责混杂、可发现性和信息缺口。
- **职责内聚与自解释性**：每篇文档应有明确职责，在其适用范围内交代必要背景、关键概念、核心行为与约束；不得以外部引用代替当前主题所必需的说明，也不为缩短篇幅而过度拆分紧密相关的内容。
- **优先维护单一权威来源**：详细规则、参数与操作说明尽量集中维护；其他文档可保留独立理解所需的简短背景、定义与结论摘要，并链接至权威位置，但不得重复维护完整规范或相互矛盾。
- **语义依赖与导航引用**：若文档必须依赖另一文档才能确定自身的核心定义或约束，属于规范性依赖，应使依赖方向明确且不成环；目录、索引和扩展阅读等导航性链接允许双向引用，不直接视为循环依赖。
- **新增文档准入检查**：先明确独立主题、目标读者、持续参考价值及现有文档无法合理承载的原因；能通过补充现有章节或更新引用解决时，不新增文件。

### 3. 选择最小必要的维护动作

| 判断 | 动作 |
| --- | --- |
| 现有内容准确且仍有用途 | **保留**，无需为整理而改动 |
| 有效行为、契约或操作方式变化 | **更新**权威内容、示例及必要引用 |
| 内容重复、职责混杂或放置不当 | **整合/重组**，保留独有知识和可发现性 |
| 当前状态说明失效且不再有持续价值 | **清理/归档**，先核实历史、引用及留存要求 |
| 存在独立且持续有用的信息缺口 | **新增**最小必要内容，并接入合适的索引或入口 |

- **当前状态文档与历史记录分离**：README、指南、API 和部署说明反映当前有效状态；ADR、CHANGELOG、迁移记录等保留必要历史，通过状态、后续记录或引用说明被取代的决策，不静默改写或删除。
- 一次性总结、临时分析和排障流水账默认不新增为长期文档；有持续价值、明确要求或留存义务时除外。常规任务结果直接在变更说明中汇报。
- 删除、合并、迁移前确认独有信息、关键操作知识和历史记录已保留或可靠承接，并修复相关入口、链接和引用；不为压缩文件数量而强行合并不同受众或职责的文档。

### 4. 核验内容并简要汇报

- 根据可靠来源核对文件路径、命令、配置项、环境变量、API 字段、版本约束及架构关系；条件允许时实际验证重要命令与示例。
- 检查受影响的导航、相对链接、锚点及交叉引用；存在文档生成源时优先修改源文件，而非仅修改生成产物。
- **独立阅读与依赖复核**：仅凭受影响文档本身检查其主要职责、核心行为和适用边界是否可理解；检查必要引用是否精准、权威定义是否重复维护、规范性依赖是否成环，不将普通双向超链接误判为循环依赖。
- **新增后价值复核**：确认新内容具有独立价值、权威位置合理且无不必要的重复维护；否则调整、整合或移除，并保留独有知识和必要历史。
- 无法核实或存在分歧时标明限制，不以猜测填补细节，也不得声称未执行的验证已通过。
- 在变更说明中简述关键维护动作、原因、实际核验结果与未确认事项；未修改文档则说明原因。
